- 结论：直接换包名**不成立**（Vue props/emits/expose ↔ Custom Element property/CustomEvent/DOM 方法是两套契约），必须补门面；`canvas` 与 `common` 的致命差异：`:initial-template/:fields/:fonts/函数型 :upload-image` 走 `setAttribute` 会字符串化、`@save` 首参是 Event 而非 JSON 字符串、`getTemplateJson()` 返回对象 vs 字符串；另外 canvas 独有 `PrintHtmlPreview`(280 行 SFC)、`provideToolbarOverflow`/指令(233 行)、`DEFAULT_DEMO_DATA` 导出。
- 新增文件：`src/vue3/{PrintDesigner,PrintHtmlPreview,previewStyle,toolbarOverflow,index}.ts`、`src/vue3/__tests__/vue3-compat.spec.ts`(9 例)、`vite.vue3.config.ts`。门面用纯 TS `defineComponent` + `h()`（不引 `@vitejs/plugin-vue`、宿主不用配 `isCustomElement`）；`PrintHtmlPreview` 的 scoped CSS 改成 `.pcv3-preview` 前缀 + 幂等注入 head。
- **四个坑**：① 门面通过 package self-reference `import { definePrintDesigner } from '@worm-vue3-print/common'` 取注册函数，子构建 external 掉全部 `@worm-vue3-print/*` 才不重复打包；② `tsc -p tsconfig.build.json` 遇 self-reference 报 TS2209，必须给 `tsconfig.build.json` 加 `"rootDir": "src"`；③ 纯 TS `expose()` 不像 `defineExpose` 宏那样并入组件实例类型，需用 `WithExposed<T>` 条件类型包装构造签名，否则 demo 的 `InstanceType<typeof PrintDesigner>` 在 vue-tsc 下报错；④ 子构建必须 `emptyOutDir: false` 且排在主构建之后。
