实测结论（全部有据）：

## 诊断：80×60mm 自定义纸模板出现「空白第一页」（已定位，未改代码）

用户模板 `/Users/worm/Downloads/template-1789810665760.json`：CUSTOM 80×60mm、四边 margin 10mm、矩形 top1/高38 + 文本 top6.82/高5.3。现象：渲染出 2 页，第 1 页空白。

根因（已用临时 Playwright 探针复现，探针已删）：
1. 内容区可用 40mm；`pagination-engine.ts` 的 `remaining = contentHeight − overlayH − SAFETY_MARGIN(2) = 38mm`。
2. 矩形与文本纵向相交 → 隐式聚类成一个分页单元，单元高 = 39−1 = 38mm，正好顶满预算。
3. 浏览器测量 `browser/dom-executor.ts:73 readMeasurements` 用 **`offsetHeight`（整数 px，向上取整）**：38mm = 143.62px → **144px → 38.1mm**，`38.1 > 38` 判定放不下
   （同一元素用 `getBoundingClientRect().height` 得 143.609px = 37.9966mm，不会触发——这是复现与否的关键差异）。
4. `pagination-engine.ts:290 finishPage()` **无条件 push 当前页**，此时 `currentPage` 为空 → 产出空白首页；元素随后落到第 2 页（`pageBroken` 后 renderTop 整体平移：矩形 1→0、文本 6.82→5.83）。

待修（用户未拍板，未动代码）：
- A. `finishPage()` 加空页守卫（`currentPage.length === 0` 直接返回）——治「空白页」，代价最小。
- B. `readMeasurements` 改亚像素精度（`getBoundingClientRect().height`，表格行高同理）——治「0.1mm 级舍入误判」，可能影响既有测试期望值。
- C. 判定加容差（如 `<= remaining + 0.5`）或把 SAFETY_MARGIN 2→1mm——治「边界抖动」，有全局影响。
- 用户侧临时规避：矩形高度降到 ≤36mm，或上下边距降到 8mm。

## 文字溢出三形式：截断 / 自动缩小 / 自适应行高

需求：文本元素与表格单元格文字过多时支持三种形式。用户拍板：截断=单行省略号；缩小到底后转截断；覆盖 `text` + `longText` + 单元格。

**核心设计（已实施，这是本项目处理「依赖真实排版」类能力的范式）：**
- `TextFit = 'clip' | 'shrink' | 'autoHeight'`；`designer/types.ts` 的 `ElementOptions` 增 `textFit/shrinkMinFontSize/wordWrap`，`TableCell` 增 `textFit/shrinkMinFontSize`。
- 纯逻辑集中在新文件 `render/text-fit.ts`（无 DOM，三端共用）：`resolveElementTextFit` / `resolveCellTextFit` / `resolveShrinkMinFontSize` / `roundFontSize` / `floorFontSize` / `cellFitKey` / `parseCellFitKey` / `cellFitCapMm`。经 `designer/index.ts` 再导出，画布与打印端共用同一判定。
- **自动缩小的关键取舍：在测量趟用真实排版引擎二分，再把结果回写模板**。`browser/text-fit-dom.ts` 的 `fitTextNode`/`applyTextFit` 跑在页面上下文（`EXECUTOR_VERSION` 升 `'2'`，`EXECUTOR_TARGETS.applyTextFit='document'`）；`ports.ts` 的 `measure` 改为返回 `{measurements, fits}`；`print/apply-text-fit.ts` 的 `applyTextFitSizes` 把 fits 写回绑定后的模板（元素 `options._fitFontSize`、单元格 `fittedFontSize`，覆盖 `_renderRows`/`_subtotalTemplates`/`_summaryRows` 三类行），最终趟据此渲染 → 测量/出图同口径，浏览器/Node/Electron 字号一致。
- 写回一律 `floorFontSize`（向下取两位），**不能四舍五入**：否则测量趟按 9.623pt 排版、最终趟按回写的 9.62pt 渲染会亚像素错版。
- `overflows()` 同时判纵向与横向：nowrap 时高度放得下但整行被裁，必须按 `scrollWidth > clientWidth` 判。
- 单元格可用高度 = 所跨行高之和 − 上下内边距 − 塌陷边框一半（`cellFitCapMm`，`border-collapse:collapse` 下每格只占自身边框的一半）；画布与打印端共用该函数。
- 设计器画布复用 `fitTextNode`：新增 `composables/useShrinkFit.ts`（`watchEffect(flush:'post')` + `nextTick`，含 `restoreFitted` 复原「从自动缩小切回截断」后残留的字号），保证设计态字号 = 出纸字号。

**坑与经验：**
- `html-generator.textStyle` **只应对缩放结果取整**，不能对全部字号取整——否则存量模板的 12.345pt 会被悄悄改成 12.35pt（超出需求的行为变更）。
- `generateHtml(tpl, [], data, {})`（非测量趟 + 空 pageLayouts）产出**空 body**：最终趟 HTML 必须经 `paginate` 后才有元素，端到端断言最终 HTML 要走 `prepareDocument`。
- `data-fit*` 标记两趟都输出（测量趟要用、最终趟惰性残留），避免某条渲染分支漏带标记而静默不缩放。
- 二分测试的期望值不能靠推理猜：`scrollWidth = 2×fontSize` 的 stub 下「最大可放字号」恰好是 5.25pt，不是下限 3。改断言为「内容宽 ≤ 上限 + 容差，且 +0.2pt 就超」才稳。
- 未知限制（已写进文档，待用户拍板）：`renderScreenshot` 不跑测量趟，自动缩小元素在截图接口产物中按基准字号渲染并裁剪；要修需让截图先测量再出图（多一次页面加载）。
