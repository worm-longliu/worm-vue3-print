## 修复：多页移动后页签名漂移重名（print-canvas）
- 现象：多页设计中把「页面 4」左移后，原「页面 1」页签显示成「页面 2」，与已存储的「页面 2」重名。

- 修复（packages/print-canvas/src/composables/useDesignerState.ts）：
  1. `resolveInitialPages` 给无名页面补存固定默认名 `页面 ${i+1}`（存储级，不再随索引漂移）；

## 条码点对齐落地（承接上条，本轮收尾）
- 实现：`render/barcode-dot.ts`（`resolveBarcodeDotLayout` + 模块制常量 `BARCODE_QUIET_ZONE_MODULES/BARCODE_BAR_HEIGHT_MODULES/BARCODE_TEXT_FONT_SIZE_MODULES/BARCODE_MARGIN_BOTTOM_MODULES`），经 `designer/index.ts` 导出供画布复用；`CodeRenderOptions` 增 `printerDpi/targetWidthMm/targetHeightMm`；`ElementOptions` 增 `printerDpi`。
- 契约：框宽→框高复核→不低于 minDotsPerModule；**框放不下整数点布局时返回 null（退像素尺寸），不为对齐而让条码溢出元素框**。
- 关键坑（实测）：点对齐后的 mm 尺寸若走 `<img src="data:image/svg+xml">`，Chromium 会把内在尺寸取整到整数 CSS px → 24.7744mm 实画 24.6063mm（**偏 0.68%，少 1.34 个打印点**）且 x/y 缩放不一致，点对齐失效；改为**内联 `<svg>`** 后 24.7706mm（偏 0.015%，≈0.03 点，打印取整即 198 点）。故 `codeImgHtml` 在点对齐分支走 `inlineCodeSvgHtml`（不再套任何 CSS 缩放），并据此把元素条码从 fill 改为 shrink-to-fit。
- 静区：jsbarcode `fixOptions` 是 `marginTop || margin` 形式 → 显式 `margin:0` + `marginLeft/Right:10模块` + `marginBottom:2模块` 可只留左右静区（上下留白会吃掉元素高度）。happy-dom 实测 viewBox `0 0 99 44`（79 模块 + 左右各 10）。
- 画布/出图同源：jsbarcode 参数统一以「模块」为单位再乘 `unitPerModule = max(1, barWidth/2)`，归一到「1 单位 = 1 模块」再算点对齐；`fontSize` 是相对条高的用户单位（不是 pt），CodeGroup 标签已改口径。
- CodeGroup：点对齐时 `v-if` 移除条宽倍率/缩放模式/最大宽高（v-show 只隐藏不移除 DOM，测试用控件数量断言更稳）。

## 条码尺寸统一结算：条宽 → 打印机 dpi → 等比缩小（行为变更，承接前三条）
- 用户口径（已当面确认两个选项）：①宽度足够时按**条宽自然尺寸**渲染、不放大填满；②**没设 dpi 时也按条宽尺寸**渲染（不再拉伸填满元素框/单元格）；③**设了 dpi 时 dpi 优先适配**（吸附整数打印点）；④可用宽度不足时**等比缩小**。
- 实现：`render/barcode-dot.ts` 用 `resolveBarcodeSize` 替换原 `resolveBarcodeDotLayout`（连同 `BarcodeDotLayout`/`minDotsPerModule`/`millimetersToDots` 一并删除，全仓仅 4 个调用点：browser-code-renderer、BarcodeElement.vue、CellBarcode.vue、单测）。新导出：`barcodeUnitsPerModule`、`barcodePreferredModuleWidthMm`、`barcodeAvailableBoxMm`（可用框并入 maxWidth/maxHeight，画布与出图共用同一上限口径）。
- 结算规则：每模块首选宽 = `barWidth/2 × 0.25mm`；有 dpi → `round(首选mm × dpi/25.4)` 点（≥1），上限 `floor(可用mm/module × dotsPerMm)`，取小者；连 1 点/模块都放不下才放弃点对齐退回连续等比缩放（此时 dotsPerModule=null，但绝不溢出可用框）。宽高始终乘同一个模块宽 → 等比不变形。
- 出图端：`renderBarcodeSvg` **总是**写 mm 尺寸且**不做任何取整**（toFixed 会把「恰好整数点」推离整数约 2e-6 点，core 单测 toBeCloseTo 默认 5e-7 会挂）；`html-generator.codeImgHtml` 条形码**恒内联 `<svg>`**（不再有 `<img>` 分支），删除 `fill` 参数，`fit` 对条码失效、`maxWidth/maxHeight` 改由 `barcodeAvailableBoxMm` 并入 targetWidthMm/targetHeightMm。
- 画布：BarcodeElement/CellBarcode 用同一份函数算样式 mm 宽高；`.cell-barcode svg` 的 CSS 由 `width/height:100%` 改为 `max-width/max-height:100%`（否则 CSS 覆盖属性导致尺寸失控）。
- UI：条码**不再提供「缩放模式」**（拉伸必破整数条宽），条宽改为常显（hint 随是否设 dpi 切换），最大宽高常显作为上限；两个属性面板与下拉/数字输入数量断言同步调整。
- 测试：core 694 / canvas 304 / render 25 / client 19 / print-client 90 全绿，架构守卫与全量构建通过；services/print-render 的 multipage 集成用例首轮会因浏览器冷启动超时 5s 偶发失败，单跑即通过。
- 坑：happy-dom 的 style 属性序列化会把 mm 截断到 6 位小数（≈1nm）→ 画布侧断言「折算回整数点」需放宽到 1e-4，core 纯函数侧可严格到 1e-6。

## 系统变量在表达式内参与运算失效（根因与修法）
- 现象：`{ADD(pageIndex,1)}`、`{pageIndex + 1}`、`{DATE(printDate,'YYYY')}` 打印出来是原文，设计器预览却有值。
- 根因：`bindData` 的表达式上下文只有业务数据，没有系统变量；求值失败时 `evaluateTemplate` 降级保留原文。而 `{pageIndex}` 能用，是因为它保留原文后由 `html-generator` 出图阶段做**文本替换** `replace(/\{pageIndex\}/g, pageNum)`——只对「整括号就是一个变量」生效。设计器预览单独注入了 `resolveSystemVariables()`，所以两边不一致。
- 修法：① `bindData` 入口 `data = { ...resolveSystemVariables(), ...printData }`（业务数据同名优先），使 `printDate/printTime` 绑定即可求值；② 引用 `pageIndex/totalPages` 的表达式在绑定阶段**保留原文**并写 `options.rawFormatter`（细胞同理写 `cell.rawFormatter`），测量趟按原始文本测量最保守；③ `html-generator.renderPage` 用新增的 `withPageNumbers(template, pageVars)` 按该页页码重算 formatter，并把 `pageVars` 放进 `RenderCtx` 供表格 `resolveCellContent` 使用；小计行重算时把 pageVars 并入上下文并清空 rawFormatter（否则二次重算会丢 `rows`）。无 rawFormatter 的模板走快速路径，存量产物逐字不变。
- 测试：`src/render/page-number-expression.test.ts`（8 例：绑定阶段、逐页替换、运算/函数、页眉、表格单元格）。
