# 多音字与抖音字幕

## 为什么不用 SSML

现有 Edge TTS 免费端点不能可靠执行 `<phoneme>`，可能把标签当文本朗读。流水线采用双轨文本：

- `display`：剧本原始台词，进入卡片字幕、烧录字幕和 SRT。
- `say`：只喂给 TTS 的文本，可用唯一读音汉字替换多音字。

两轨在 `polyphone.json` 中逐句对应，`polyphone.md` 留判定理由，`verify.mjs` 会把多短条重新拼成原句，检查原文未被替换字污染。

## 识别与纠正

横屏 `voiceover.mjs`、竖屏 `portrait/voice.mjs` 都先执行 `polyphone.py`，失败即停止，不消耗 TTS 额度。

1. pypinyin 按整句计算上下文读音；与词典默认底音不同的风险位置必须显式处理。
2. 打印和技术口播风险表中的多读字必须认下，不允许带着未知读音出片。
3. 人工根据词义填写词级 `read`；词典也会误判，例如“长连接”读 cháng、“重试”读 chóng，不能机械接受自动结果。
4. 有唯一读音替换字时锁定 `say`；没有时优先改措辞，或 `keep` 保留原文并通过听审确认。
5. 剧本未出现的注解会报过期错误，避免改台词后旧规则误伤其他词。

```json
{
  "read": [
    ["长连接", "chang2", "长连接读 cháng"],
    ["重试", "chong2", "再次尝试读 chóng"],
    ["模板", "keep", "读 mú；无唯一替换字，保留原文并听审"],
    ["npm", "=N P M", "术语按字母读，仅替换 TTS 文本"]
  ],
  "accept": [["行", "xing2", "放行读 xíng；同行等词由 read 精确覆盖"]],
  "scenes": [{
    "name": "示例",
    "voiceover": "原始台词。",
    "read": [["银行", "hang2", "金融机构读 háng"]]
  }]
}
```

顶层 `read/accept` 全片生效，场景 `read` 只在本场生效。锁定读音必须用两字以上的词锚定语义，禁止单字全片替换。目标读音使用 pypinyin `TONE3`，如 `hang2/chong2/dei3`。

## 听审不是可选项

`polyphone-audio.mjs` 截取 `display !== say` 的替换句，以及 `needsReview=true` 的人工判定风险句（包括 `keep` 和 `accept`），输出 `polyphone-audio.m4a` 和两轨文本清单。短字幕增加后，听审窗口按 `sentence` 编号合并，不再假设一句只有一条字幕。

自动门禁证明“风险已处理、替换字唯一、字幕保真”，不证明合成器最终发音一定正确。普通 ASR 会把同音字仍转写成相同汉字，不能单独作为读音证据；未做可靠音素级验证时必须写明“未做 ASR 自动核验，以人耳听审为准”。听审发现误读就改 `read` 或措辞，整链重跑。

## 短字幕与平台避让

共用 `subtitles.mjs`：

- 按 `，、；：。！？` 组成语义短条，超长无标点句硬切；不丢弃原字符。
- 每条最多两行；两行时优先在标点处均衡换行。
- 在同一真实发音时长内按字数分配时间，末条吸附句尾，保证连续且无舍入缝隙。
- 竖屏默认每行 16 字，ASS 将换行写成 `\N`；横屏默认每行 20 字，叠加层用 `white-space: pre-line`。

竖屏沿用 1080×1920、字号 56、`MarginV=340`；卡片核心内容位于中央 3:4 算术区 y240–1680。右留 168px、底部留 520px、横屏底部 64px 都是项目经验值，不是抖音公开官方标准。上传前必须由用户在平台预览确认昵称、简介、右侧按钮和进度条没有遮挡。
