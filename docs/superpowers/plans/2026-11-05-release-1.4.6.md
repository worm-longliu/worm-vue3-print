# V1.4.6 发布实施计划

## 范围与边界

- 发布当前工作树中的 MCP 模板摘要、原子 Patch、revision 缓存及耗时日志代码。
- 正式版版本号为 `1.4.6`，日期为 `2026-11-05`。
- npm 通过 GitHub CLI 手动触发工作流，发布 `core`、`canvas`、`common`；同次工作流发布 `skills`，四包均为 `1.4.6`。
- 重新构建桌面客户端全平台安装包，生成校验和并上传到 GitHub Release。
- 同步发布更新后的 MCP 技能包；视频只写忽略目录，以付款申请单演示 1.4.6 MCP 特性，不自动上传抖音。

## 任务 1：代码与发布机制验收

1. 审查 MCP 与客户端改动，确认摘要投影、Patch 防覆盖、日志脱敏及测试覆盖符合既有边界。
2. 运行 `npm test -w @worm-vue3-print/mcp` 和 `npm test -w @worm-vue3-print/print-client`。
3. 为 `publish-npm.yml` 增加可选 `publish_skills` 输入，默认保持原行为；本次传 `true`。
4. 若测试暴露问题，先修复并重跑相关测试，再进入版本修改。

## 任务 2：版本与发行载体

1. 同步根包、工作区包及 `package-lock.json` 的版本和工作区依赖范围。
2. 更新中英文更新日志、设计器内置更新日志和 `.github/release/notes.md`，说明本版 npm 四包同号发布。
3. 将 README 客户端直链和当前版本说明切到 `v1.4.6`，不沿用旧安装包。
4. 运行 `node scripts/check-release-carriers.mjs --pre`，修复所有 `FAIL`，并核对 `WARN`。

## 任务 3：本地完整验证与客户端打包

1. 运行 `npm run lint:print-architecture`、`npm run build`、`npm test`。
2. 执行 `npm run pack:client` 构建 macOS/Windows 安装包。
3. 执行 `npm run pack:client:linux` 构建 Linux 安装包。
4. 执行 `node scripts/pack-client-release.mjs v1.4.6`，核对六件安装包及 `SHA256SUMS.txt`。

## 任务 4：提交、标签与 GitHub 发布

1. 用 `git diff` 审查最终改动，仅提交本次代码、发布配置、文档和计划。
2. 推送 `master` 与附注标签 `v1.4.6` 到 GitHub，并按仓库既有双远端约定同步 Gitee。
3. 使用 `gh workflow run publish-npm.yml -f tag=v1.4.6 -f dry_run=true -f publish_skills=true` 干跑。
4. 干跑通过后传 `dry_run=false` 正式发布 `core/canvas/skills`，再触发 `publish-common.yml`。
5. 触发 `release.yml` 创建正式 GitHub Release，上传客户端安装包与校验和。

## 任务 5：发布后证据

1. 用 `gh run watch` / `gh run view` 确认所有工作流成功。
2. 用 `npm view` 证明 `core/canvas/common/skills=1.4.6`。
3. 用 `gh release view v1.4.6` 核对 Release 非草稿、非预发布，六件安装包和校验和齐全。
4. 下载校验和并执行 `sha256sum -c` 或平台等价命令，确认上传产物未损坏。

## 任务 6：1.4.6 特性视频

1. 委托 Qoder `Qwen3.8-Flash`，加载 `making-douyin-videos` 技能，以 demo 付款申请单为操作画布。
2. 视频事实仅取 1.4.6 的 MCP 摘要读取、原子 Patch、链式 revision、缓存、pending 与耗时日志，不混写旧版分页能力。
3. 本地生成成片、SRT、多音字与听审台账、4×3/3×4 封面、恰好五标签的抖音文案并运行技能验收；不自动上传。
