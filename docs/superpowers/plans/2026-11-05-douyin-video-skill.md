# 抖音视频技能整理实施计划

**目标：** 把现有横屏、竖屏流水线整理成可被任意项目 Agent 使用的技能，并统一多音字、抖音字幕、封面和发布文案契约。

**架构：** 技能入口只保留路由和强制门槛；可复用流水线与真实默认剧本放在 `assets/pipeline/`，详细写作和验收规则放在 `references/`。本地 `.video/` 仍是运行目录，成品、录屏和中间文件继续被 Git 忽略。

**技术：** Node.js ES modules、Python、pypinyin、Edge TTS、Playwright、FFmpeg。

## 约束

- 沿用现有 `cover-douyin.html` 和中心裁切，不另设计封面。
- 必须交付 4:3（1440×1080）和 3:4（1080×1440），同时保留 16:9、9:16 母版。
- 字幕保留原始汉字，同音替换只进入 TTS；短条最多两行，参数是项目经验值而非平台官方规范。
- `douyin-copy.md` 必须含发布文案和恰好 5 个不重复标签。
- 不自动上传抖音，不在验证中调用 TTS。

## 任务

### 1. 行为测试

- 为字幕短条、两行折行、时间轴守恒写测试。
- 为文案恰好五个标签、多音字“银行”锁定与字幕原文保真写测试。
- 为引导脚本可在空目录生成完整流水线写测试。
- 先运行并确认因实现缺失而失败。

### 2. 通用流水线

- 收录现有横屏、竖屏脚本、封面模板和真实剧本。
- 抽取共用字幕函数，横屏和竖屏都在配音阶段生成相同短条时间轴。
- 竖屏配音接入现有 `polyphone.py`，与横屏共用 `display/say` 双轨。
- 新增抖音文案生成器和单剧本验收器。
- 新增空目录引导脚本，不覆盖既有本地流水线。

### 3. 技能文档

- 重写入口，明确选链路、剧本编写、多音字门禁、字幕、封面、发布与验收。
- 将剧本字段和写作风格、平台交付细则拆到按需读取的 references。
- 删除“竖屏没有多音字处理”的过期说明，五个标签改为硬约束。

### 4. 验证

- 运行 Node 测试、Python 多音字测试和脚本语法检查。
- 在临时目录引导流水线并实际生成封面，以 ffprobe 核对四种尺寸。
- 运行技能 `quick_validate.py`、`npm run build` 和最终 `git diff` 审查。
