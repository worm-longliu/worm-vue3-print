# 模板设计器

`PrintDesigner` 是 `@worm-vue3-print/canvas` 导出的 Vue 3 可视化设计组件。
纯 HTML/CSS/SVG 原生控件实现，不依赖 Element Plus 等 UI 库，也不包含任何宿主业务逻辑
（不发网络请求、不含路由/租户概念）；保存、字段、上传等能力全部由宿主注入。

## 一、最小接入

```ts
import { PrintDesigner, createDefaultTemplate } from '@worm-vue3-print/canvas'
import type { PrintBusinessField, TemplateData } from '@worm-vue3-print/canvas'
// 发布包对外只有一个样式入口（源码别名模式才用 native-controls.css）
import '@worm-vue3-print/canvas/style.css'
```

```vue
<PrintDesigner
  ref="designerRef"
  :initial-template="templateData"
  :fields="fields"
  :is-edit="true"
  :show-help="true"
  @preview="onPreview"
  @save="onSave"
/>
```

## 二、Props

| Prop | 类型 | 说明 |
|---|---|---|
| `initialTemplate` | `TemplateData \| MultiPageTemplateData` | 初始模板。整体替换该引用即可重载画布（会记录一次历史，撤销可回退），用于宿主实现「加载示例」「切换模板」。传 `{ version: 1, pages: TemplateData[] }` 即载入多页面模板，载入时按 core 的 `normalizeTemplate` 归一化 |
| `initialElements` | `RuntimeElement[]` | 直接以运行时元素数组初始化（与 `initialTemplate` 二选一的高级入口） |
| `fields` | `PrintBusinessField[]` | 业务字段，宿主查询后传入；是字段树、表达式编辑器、绑定下拉的唯一数据源 |
| `isEdit` | `boolean` | 是否编辑态 |
| `uploadImage` | `(file: File) => Promise<string>` | 图片元素上传适配器，返回可访问 URL；不传则图片上传不可用 |
| `uploadDesignBackground` | `(file: File) => Promise<string>` | 设计背景（定位底图）上传适配器，返回可直接访问的完整图片路径；不传则上传入口禁用。背景仅设计画布显示，不进入预览与打印 |
| `showHelp` | `boolean` | 是否展示帮助入口，默认开启；传 `false` 关闭帮助按钮与帮助弹框 |
| `fonts` | `PrintFontDeclaration[]` | 模板级字体声明：设计器注入 `@font-face`、在字体下拉中列出，保存/预览时同步写入模板 JSON 的 `fonts` 字段。声明里的 `label`（业务名，如「马善政毛笔楷书」）用于字体输入框与下拉展示，也参与搜索匹配；写入模板的始终是 `family`（族名）。`files[].url` 支持绝对 URL（推荐，三端都取同一个地址）与相对路径：相对路径在浏览器端按页面 origin 解析（与画布一致），出图端按 `fontBaseUrl`（缺省回落 `baseUrl`）解析。**字体站点必须返回 `Access-Control-Allow-Origin`**，否则出图端跨源加载失败、静默回退系统字体。未声明的字体名仍可直接输入，但能否出图取决于出图端是否装有该字体。设计器**不预置任何字体、也不内置字体名档位**：新建元素与新建表格都不带 `fontFamily` / `tableDefaultFontFamily`，未手工配置时出图不输出 `font-family`、由渲染端系统默认字体承接，字体下拉只列宿主声明的字体。**字体与字体文件的授权由使用者自查**——微软授权字体名不允许随镜像或安装包再分发，OFL/Apache 系（思源黑体、站酷、马善政等）可自由分发。跨端字面要求严格仍应走字体声明（服务端渲染容器内中文只有 `fonts-noto-cjk`） |

组件不持有模板名称、业务类型等元信息，也不内置「加载默认布局」这类业务入口，由宿主自渲染按钮。

## 三、事件

| 事件 | 参数 | 触发时机 |
|---|---|---|
| `save` | `(json: string)` | 工具栏保存；`json` 为当前画布模板 JSON 字符串，宿主持久化 |
| `preview` | 无 | 工具栏预览；宿主通过 ref 取 JSON 后自行弹出 `PrintHtmlPreview` |

## 四、实例方法（ref）

| 方法 | 说明 |
|---|---|
| `getTemplateJson()` | 取当前画布模板 JSON（对象），用于保存与预览；**单页返回裸 `TemplateData`，2 页及以上返回 `{ version: 1, pages }`**。宿主经 `fonts` prop 声明字体时，返回结果会带上同一份 `fonts` |

多页面模式另有实例方法（与 `useDesignerState` 同名同义）：`pages`（当前页面数组）、`activePageIndex`（当前激活页下标）、
`switchPage(index)`、`addPage()`、`duplicatePage(index)`、`deletePage(index)`、`renamePage(index, name)`、`movePage(from, to)`。
宿主可用它们自建页面栏，直接修改 `pages` 里的单个页面对象不生效，请走上述方法。

## 五、业务字段 PrintBusinessField

```ts
interface PrintBusinessField {
  id?: string
  fieldKey: string    // 打印数据中的完整路径，如 supplier.name、goods.spec
  fieldLabel: string  // 字段显示名
  fieldType: string   // 字段类型；'list' 表示明细列表字段（表格数据源选项）
  sortOrder: number   // 排序
}
```

分组规则：扁平传入，UI 按 `fieldKey` 首段自动分组——无点且作为其它字段前缀的记录为分组容器
（如 `supplier`、`goods`）。拖拽/双击叶子字段插入的表达式即为完整路径（如 `{goods.spec}`）。

## 六、宿主能力适配器

开源核心不直接发起网络请求，可选适配器由宿主实现：

```ts
import type { UploadImageFn, UploadDesignBackgroundFn } from '@worm-vue3-print/canvas'

// 图片上传：宿主调自己的文件服务，返回可访问 URL
const uploadImage: UploadImageFn = async (file) => {
  const form = new FormData()
  form.append('file', file)
  const res = await fetch('/api/files/upload', { method: 'POST', body: form })
  const { url } = await res.json()
  return url
}

// 设计背景：宿主上传后必须返回完整图片路径（绝对 URL / 完整可访问地址），不配合 baseUrl
const uploadDesignBackground: UploadDesignBackgroundFn = async (file) => {
  const form = new FormData()
  form.append('file', file)
  const res = await fetch('/api/files/design-background', { method: 'POST', body: form })
  const { url } = await res.json()
  return url
}
```

> 高级场景也可通过注入键 `UPLOAD_IMAGE_KEY`、`UPLOAD_DESIGN_BACKGROUND_KEY`（从 canvas 包导出）在深层子组件提供上传实现。

## 七、模板模型 TemplateData

```ts
interface TemplateData {
  paperSize: PaperSize                 // 内置纸型 | 'CUSTOM' | 'CONTINUOUS'
  orientation: 'portrait' | 'landscape'
  name?: string                        // 页面名（多页面模板的页签文案与错误上下文；渲染端忽略）
  outputRotation?: 0 | 90 | 180 | 270  // 内容旋转角度，默认 0；90/270 时出纸纸张宽高互换；拼版下按每格内容旋转并互换每格占位
  margins: { top: number; right: number; bottom: number; left: number } // mm
  header: { height: number; elements: TemplateElement[] }
  footer: { height: number; elements: TemplateElement[] }
  elements: TemplateElement[]          // 内容区主体
  unit?: 'pt' | 'mm'                   // 新模板固定 mm；旧数据无此字段按 pt 迁移
  customWidth?: number                 // CUSTOM 纸宽 / CONTINUOUS 纸宽（默认 80），mm
  customHeight?: number                // CUSTOM 纸高，mm
  pageBackground?: string              // 页面背景色，默认白色
  watermark?: WatermarkOptions         // 水印配置
  guides?: AlignLine[]                 // 手动参考线（仅设计态，渲染端忽略）
  designBackground?: {                  // 设计背景（定位底图），仅设计画布显示，渲染端忽略
    src: string                         // 宿主上传返回的完整图片路径
    rotation: 0 | 90 | 180 | 270        // 90° 步进旋转，默认 0
  }
}
```

元素类型共 13 种：`text`、`longText`、`image`、`table`、`flowList`、`hline`、`vline`、`rect`、`oval`、
`barcode`、`qrcode`、`html`、`pageNumber`；定位与尺寸全部写在元素 `options` 中，单位毫米。

**元素级旋转（`options.rotate`）**：度，绕元素自身中心，归一到 0~359，缺省不旋转。出纸按旋转后的**外接方框**
分页与结算——底部放不下自动移到下一页（按外接方框顶落位），顶部越过页首或左右越过纸面会给出「打印将被裁切」提示。
`table`、`flowList` 与**表格下方跟随区的元素**不支持旋转（渲染保持水平，属性台也不出「旋转 (°)」行）；
`barcode` / `qrcode` 的任意角度需 385dpi 以上打印头，分辨率不够时按 90° 步进出纸，模板未声明打印头分辨率时
按声明角出纸（属性台会把角度输入置灰，只留 ±90° 步进按钮）。渲染走 CSS 独立属性 `rotate`，不占用 `transform`
（设计器拖拽与出纸互不覆盖）；旧模板里残留的 `transform` 数字键被忽略，出纸与升级前一致。

### 流式列表（`flowList`）

把一份明细列表按「每行 N 列」横着排、排满自动换行，用于中药处方笺这类一格一物、行内密排的版式
（对应 GitHub issue #5）。与表格的区别是：列只是栏位、不画格线，单元内容是一个表达式模板。

| 字段 | 面板文案 | 说明 |
|---|---|---|
| `flowColumns` | 每行列数 | **必须由模板作者指定**，不随内容自动算列数；1~12，缺省 4 |
| `flowRowHeight` | 行高 (mm) | **最小高**语义（同表格行高）：内容比它高时该行撑高，不裁字；3~100，缺省 8 |
| `flowGapX` | 单元横向间距 (mm) | 相邻单元留白，0~50，缺省 4；纵向不留缝，行距由行高承担 |
| `flowAutoSpan` | 内容过长时跨列 | 缺省关。打开后单元内容比一列宽时吃掉 2 个及以上列位；当前行列位不够就把整单元挪到下一行行首（不切词） |
| `flowMaxSpan` | 最多跨几列 | 跨列上限，**钳到 `flowColumns`**：把列数改小时这里会被一并顶回（本元素唯一改用户值的行为） |
| `formatter` | 单元模板 | **一条完整表达式**，对数组每项求值一次，列表路径就写在里面：`{drugs.name} {drugs.spec}`。属性台没有单独的「列表数据源」输入行——表达式里出现了哪个数组字段，就按它取列表 |
| `dataSource` | （可选，面板不显示） | 手工写模板时可用它显式指定数组字段名，优先级高于表达式检出；缺省时按「表达式检出 → 数据里第一个数组」兜底（同表格） |

- **列数挤不下时只提示不写值**：按字号与框宽给出「可放约 N 列」的建议行，绝不回写你填的列数（与条码「推荐条宽倍率」同一口径）。
- **跨列只在出纸生效**：画布设计态既不跑测量也不跑分页，所以设计台上永远是一列一格，跨列结果以「预览 / 打印输出」为准。
- **一框一页，不续页**：数据多过元素框高时按 `textFit` 三档处理（缺省 `clip`＝截断），不会自动排到下一页；要续排请改用表格。
- **单元是整段文本**：`{name} {spec}` 里两字段之间不会自动对齐成两列；要「剂量成列」就得把每个单元做成长度一致的模板串。

### 文字溢出显示形式（`options.textFit`）

文本元素（`text` / `longText`）与表格单元格（`TableCell`）共用同一套溢出策略，
属性面板中为「文字溢出」，模板字段为 `textFit`：

| 取值 | 面板文案 | 行为 |
|---|---|---|
| `clip` | 截断 | 超出可用高度的部分不显示；不换行（`wordWrap: false`）时单行以省略号收尾 |
| `shrink` | 自动缩小 | 自动缩小字号直到放得下；缩到下限字号（`shrinkMinFontSize`，缺省 6pt）仍放不下则退化为截断 |
| `autoHeight` | 自适应行高 | 元素高度 / 表格行高随内容增高（元素不写死高度，按内容实测高度参与分页） |

- **缺省值与既有行为一致，存量模板不受影响**：`text` 缺省 `clip`、`longText` 缺省 `autoHeight`、
  单元格缺省 `autoHeight`（单元格同时设了 `wordWrap: false` 时为 `clip`）。
- **缺省行高**：不填「行高」时，`text` 用浏览器默认（normal）、`longText` 用 **1.5 倍**（画布 / 零框架宿主 / 出纸三端同值）。
- 文本类元素的 `wordWrap`（自动换行，缺省 `true`）与单元格同名字段语义一致：
  置 `false` 为单行显示，配合截断形式即「单行省略号」。
- **`autoHeight` 关自动换行是「单行溢出」而不是省略号**：`longText` 的缺省形式正是 `autoHeight`，它保留 `overflow:visible`，
  而省略号只在裁剪容器里才画得出——该组合下纸面出**一行、越出元素右缘**（可能与邻元素叠压），要省略号请把显示形式显式设为「截断」。
  V1.3.10 及更早这一档在出纸端不生效（纸面仍按多行折行、只有画布是单行），V1.3.11 起画布 / print-common / 出纸三端同源。
- **单元格文本按换行符断行**：`wordWrap` 为 `true`（缺省）时，文本里的 `\n` 会真的换行，
  连续空格与行首空格也原样保留（与 Word/Excel 单元格一致）；置 `false` 时 `\n` 折叠为空格，
  因为那一档的语义就是强制单行。换行符只能在**表达式编辑器**（多行输入框）里录入，
  属性台的「内容」是单行输入框，粘贴多行文本会被浏览器剥掉换行。
- **英文单词不在词内断开**：可换行档按整词换行（中文仍按字断行），只有当一个单词本身
  就比列宽还长、独占一行也放不下时，才在行末兜底切一次。同一串文本里的断行位置因此
  与旧版不同，行高会被多行撑高、表格总高变长，分页也随之位移（单枚标签类模板尤其要复核）。
- 自动缩小在渲染管线的**测量趟**内用真实排版引擎二分求解，结果回写绑定后的模板再出图，
  因此预览、服务端 PDF、桌面客户端三端字号一致；页眉、页脚的文本元素同样参与。
- 模板 JSON 只需保存 `textFit` 与可选的 `shrinkMinFontSize`；
  `_fitFontSize`（元素）与 `fittedFontSize`（单元格）是渲染中间产物，只存在于绑定后的副本，不会写回模板文件。

### 多页面模板（一份文档多个版式）

一份数据要打出**版式不同**的若干页（封面 + 正文 + 条款）时，用 wrapper 描述——单页模板仍用裸 `TemplateData`：

```ts
interface MultiPageTemplateData {
  version?: 1                 // 缺省 1
  pages: TemplateData[]       // 按打印顺序排列；每项都是一份完整的单页模板
}
```

- **各页绑定同一份数据**，出纸时按 `pages` 顺序首尾相连；**每个页面模板一定从新的一页开始**（不与前一页连续拼接），不需要额外的分页元素，整份文档一次出图。
- 页面模板内部仍按内容溢出分页；页码系统变量 `{pageIndex}` / `{totalPages}` 在**份内全局连续**（跨页面模板累计）。
- 三条约束由 core 的 `normalizeTemplate` 统一校验，设计器保存/预览与渲染服务共用同一套：`pages` 至少 1 页、**各页纸张尺寸（含方向）必须一致**、**不支持连续纸与标签拼版**。错误信息带页面名，例如 `多页面模板各页纸张尺寸必须一致（第 2 页「条款」…）`。
- 各页的 `fonts` 声明在渲染时按族名**去重合并**成一份 `@font-face`，不必担心重复声明。
- 兼容性：单模板的渲染产物与旧版**逐字一致**（CSS 作用域化重构有护栏测试），存量模板与宿主零改动。

已知限制：内容旋转角度在多页面文档中取**首页**的 `outputRotation`；暂不支持按数据条件决定是否包含某页。

空白模板用 `createDefaultTemplate()` 生成（canvas 包导出）。字段类型从 canvas 包的类型导出获取：

```ts
import type { TemplateData, RuntimeElement, PrintBusinessField } from '@worm-vue3-print/canvas'
```

> 设计器的框架无关内核（吸附、对齐、组合、缩放、键盘交互等纯算法）位于
> `@worm-vue3-print/core/designer` 子路径，canvas 包只是它的 Vue 适配层；
> 非 Vue 宿主可直接基于该内核实现自己的 UI。

## 八、设计器能力一览

- 多页面：一份文档可由多个版式页面组成（如「封面 + 正文 + 条款」），共用同一份数据顺序出纸；顶部页面栏支持新增/复制/删除/重命名/排序/切换。纸张设置对所有页生效，页边距、页眉页脚、水印与内容元素按页独立；多页模式下不可拼版、不可选连续纸
- 页面旋转：属性面板「内容旋转角度」可选 0°/90°/180°/270°，支持横版设计竖版出纸（90/270 时纸张宽高互换），内容不缩放不裁切。拼版启用时按每个标签的内容旋转，90/270 时每格占位宽高互换、列数自动铺满新档位上限、行数按互换后重算（拼版摘要会显示「每格 宽×高」）
- 元素旋转：外观组「旋转 (°)」行，输入角度或点两侧按钮按 90° 步进（绕元素自身中心），带「恢复默认值」。表格、流式列表与表格下方跟随区的元素不出该行；条码/二维码在无 385dpi 以上打印头承诺时角度输入置灰并写明原因。画布所见与出纸一致（同一份判据）
- 出纸裁切提示：元素旋转后越过页首、或（含旋转后的外接方框）超出纸面左右缘时，预览层顶部常驻「出纸提示」条列出元素与超出量；点保存时也会给一次提示，**不阻断保存**。宿主可用设计器暴露的 `getGeometryWarnings()` 在导出/另存链路自取同一批文案
- 纸张预设：常用纸张、针式打印纸、标签纸、小票纸（连续纸）、连续纸五组；切到标签纸时默认取消页边距与页眉页脚（整张纸给内容区），只套用一次
- 设计背景：页面属性可上传套打底图并 90° 步进旋转，仅画布可见，预览与打印均不输出
- 画布：拖拽移动/缩放、网格与磁吸、参考线、标尺、缩放、撤销/重做、复制粘贴、多选、组合
- 面板：左侧字段树/元素/图层，右侧属性面板（位置尺寸、外观边框、数据绑定、表格行列设置、分页、水印等）
- 属性恢复默认值：任何**有出厂默认值**的属性行，标签行最右侧都有一个 ↺ 图标（与顶部工具栏同源）。当前值与默认值不同时才点亮，点一下写回默认值；悬浮提示直接告诉你会恢复成什么（如「恢复默认值（12 pt）」）。**表格单元格**的图标提示「跟随表格默认」——它清掉单元格自身的值，让该项重新继承表格级默认，而不是回到某个绝对数。**逐项生效，没有批量**：分组标题和整个元素都没有一键重置按钮。不点图标不写任何值，存量模板与出纸零变化

- 表格：Excel 风格单元格选择、行列标题/数据/小计/汇总四类行、跨页重复表头（支持多级表头，按整个表头区生效）、单元格图片/条码
- 文字溢出：文本元素与单元格支持「截断 / 自动缩小 / 自适应行高」三种形式，设计态字号即出纸字号
- 码制：条形码（jsbarcode 几何）、二维码；条形码/二维码**元素**在属性台「条码设置」分组配置码制、条宽、静区、条高、显示文本、文本字号、纠错级别，与表格单元格口径一致
- 条形码尺寸：图形**只缩不放**——每模块首选宽 = `条宽倍率/2 × 0.25mm`（倍率 2~8，可到 1mm），设了打印机分辨率再吸附到整数打印点，框放不下才整体等比缩小（拉伸会把条宽拉成非整数、出纸忽宽忽窄，所以条形码没有缩放模式）。「静区 (模块)」管的是左右两端的白边（0~20，**缺省 10**＝一维码码制要求的下限），调小即把白边换成条粗；要整体做大按「加条宽倍率 → 收窄静区 → 关掉显示文本让出文本区高度 → 加列宽/行高」的顺序调。填 0 时白边压没，紧邻文字或表格线可能扫不出，需实打验证。「条高 (mm)」只管**黑白条本体**（不含下方文字），折算粒度就是每模块物理宽，因此只能精确到它的整数倍（`barWidth=4` 时步进 0.5mm）；框高不够时**由条高让位、条宽一分不损**——填 20mm 而框只有 14.1mm 却打出 14mm 是设计如此，不是没生效，要真长出 20mm 请加行高/元素框高。**选了打印机分辨率后，「条宽（倍率）」下方还会追加一行推荐档**：按「吸附到整数打印点后每模块宽 ≥ 0.254mm（10mil 下限）」取最小倍率，203dpi 推荐 3（3 点 / 0.375mm）、300 与 600dpi 推荐 2；同时报你当前档的折算（缺省 2 在 203dpi 下是 2 点 / 0.250mm，会写明「低于下限」），半档常被吸成同一点数所以不会假称更粗。**该行只是参考，不会替你改 `barWidth`，也不进模板 JSON**
- 二维码尺寸：图形等比铺满元素框短边（设计态与出纸同一份 SVG），框内那圈白边就是「静区」，按模块计（0~8，缺省 0＝不留白边、码面贴住框边）；扫码所需静区由元素框外的白纸充当，需要 ISO/IEC 18004 推荐静区时显式填 4
- 图片缩放与取位（裁剪锚点）：「缩放模式」五档（包含／剪裁（等比铺满后裁边）／拉伸填满／原始尺寸／缩小）。「裁剪锚点」行**只在「剪裁」档出现**——只有等比铺满才会多出一条边可挪，其余档图比框小或刚好铺满，没有可裁的边。行内是位置档下拉 + **放大比例 (%)** + **水平／垂直两个数字框常驻** + 原图可视窗示意（红框就是会被打出来的那块）；某一轴挪不动时提示会直说「这一轴已贴满」，档位列表只列能动的轴。拿不到业务图片地址时（含地址仍是**未求值的 `{字段}`**），示意改用内置方形示例图（120×120 九宫格）演示取位并标注「示例图」——它**只用于示意**，不会变成画布或出纸上的图片。示意框贴住图片本身（不是面板宽），所以红框的形状就是被裁区域的真实形状：方形示例图显示成正方形。对应的模板字段是 `objectPosition`，如 `'50% 0%'`（取画面顶端）；渲染层不校验缩放模式，手写在其它档位上的 `objectPosition` 仍按原值落纸（挪的是框内空位），只是属性台不再提供入口
- 剪裁放大 `fitScale`（100~400，单位 %，仅「剪裁」档消费）：图与框同比例时，等比铺满后画面刚好等于框——一条边都裁不掉，这时把画面推大才有可裁的余量。100＝不放大（缺省，存量模板逐字不变）。落点是 `transform: scale(fitScale/100)` 配 `transform-origin` **复用同一条 `objectPosition` 值**：锚点既是取位的钉住点、也是放大的不动点，所以「贴左上」放大后打出的确实是画面左上角。画布实测（28.2mm 方框 + 120×120 方图 + 200%）：img 视觉盒 106.6px → 213.2px（比值 2.000），锚点 `0% 0%` 时图左上与框左上重合、右下各溢出 106.6px，锚点 `100% 100%` 时反过来，提示同步报「水平可挪 28.2mm、垂直可挪 28.2mm」；改回 100 即 `transform: none`。超出框的部分由元素框／单元格盒的 `overflow:hidden` 裁掉，不改变元素框尺寸与出纸占位
- 图片单元格的裁剪：与独立图片元素同构，但**只在「剪裁」档生效**。单元格选了「剪裁」，图片外框就钉在可用框高（所跨行高之和扣除内边距与塌陷边框），`<img>` 撑满该盒，`fit`、「裁剪锚点」与「放大比例」真的裁得动；代价是含图单元格不再被图片撑高，出纸行高按声明值走（实测：声明 12mm 的行，改前被 90px 的图撑到约 23.8mm，改后回到 12mm，取顶打出图顶端红带、取底打出底端蓝带）。其余档（缺省／包含／拉伸填满…）保持原状——行高仍由内容决定，图片按内在尺寸占位，存量模板逐字不变。同行若有文本按「自适应行高」撑高，行会高于声明值，而图片仍钉在声明高度上。需要限制图片大小请用单元格「最大宽高 (mm)」，钉盒后它仍是上限
- 条码尺寸：条形码**元素**与**单元格**都按「条宽 → 打印机 dpi → 等比缩小」结算（三个运行端同一份算法）：默认条宽下每模块 0.25mm，可用框装得下就按原尺寸落纸（**不拉伸填满**，放大只会让条宽变成非整数点）；设置了「打印机分辨率」（`printerDpi`，203/300/600）时该尺寸吸附到整数打印点，分辨率优先于条宽的精确毫米值；可用宽度不足时整体等比缩小（先按整数点逐级缩小，1 点/模块仍放不下才退化为连续等比缩放）。需要更大条码请调大「条宽」，需要上限请用「最大宽高 mm」；条形码不提供缩放模式。「条高 (mm)」按**条宽优先**结算：core 先按缺省 30 模块探一趟，拿到模块数与文字区实测占用后再折算条区模块数，必要时按目标条高重出第二趟——因为每模块宽 = 框宽 ÷ 模块数，而模块数要出图后才知道；未填条高、或折算结果恰是缺省档时只走一趟，存量模板逐毫米不变。单元格的可用框按所跨列宽/行高扣除内边距与边框计算，表格未配置列宽时宽度不参与结算
- 系统变量：`{pageIndex}`、`{totalPages}`、`{printDate}`、`{printTime}`
