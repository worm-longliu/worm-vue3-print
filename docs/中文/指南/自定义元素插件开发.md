# 自定义元素插件开发指南

> 适用版本：1.5.0 起。完整设计决策见 `docs/superpowers/specs/2026-11-14-custom-element-plugin-design.md`。
> 可复制的最小脚手架：`examples/custom-element-plugin/`（一个 `signature` 元素）。

## 1. 这套机制解决什么

主体（`print-core` / `print-contract` / `print-canvas`）只保留**通用机制**：注册表、双模式校验、
动态 kinds、通用资产协议、属性台 tab。任何具体元素（图表、签名、二维码变体、自定义业务块）
都由独立可选包用一份 `defineElementPlugin` 描述符声明，宿主 `import` 一次即全部生效：

- 设计器素材卡、画布组件、「自定义属性」tab；
- 模板校验、AI/MCP 的 `print_element_kinds` 与 draft 枚举；
- 数据绑定、浏览器预览与打印、服务端 PDF、Electron 静默打印；
- 分页 / 拼版 / 批量 / 多页模板的渲染器透传。

**历史模板零迁移**：顶层 `plugins` 清单是可选的；不声明时走 legacy 宽松模式，
已装包宿主不用改装配代码（§4.3 兼容别名无限期保留）。

## 2. 五步做出一个插件

### 第 1 步：写描述符（唯一知识来源）

新建 `plugin.ts`，用纯 TS 声明 `kind` / `binding` / `render`。**不要 import Vue SFC** ——
这个文件会被 `/node` 子路径打包进服务端与 Electron 主进程。

```ts
import { defineElementPlugin } from '@worm-vue3-print/core/designer'
import type { PrintElementPlugin } from '@worm-vue3-print/core/designer'

export const MY_PLUGIN: PrintElementPlugin = defineElementPlugin({
  kind: {
    id: '@acme/my-element', version: '1.0.0', type: 'myElement', label: '我的元素',
    icon: '◇', fixedHeight: true,
    requiredOptionKeys: ['left', 'top', 'width', 'height', 'myText'],
    optionMeta: { myText: { kind: 'text', label: '文字', default: '占位' } },
    defaultOptions: () => ({ width: 60, height: 20, myText: '占位' }),
    notes: '给 print_element_kinds 看的说明',
  },
  binding: { bind: (options, data) => ({ myText: String(data.myField ?? options.myText ?? '') }) },
  render: {
    createRenderer: () => ({ render: spec => `<svg ...>${String(spec.myText ?? '')}</svg>` }),
    html: spec => `<svg ...>${String(spec.myText ?? '')}</svg>`,
  },
})
```

### 第 2 步：声明合并（让宿主 TS 认识新类型）

`type-augmentation.ts` 里扩展空 `PluginElementTypeMap` 与 `ElementOptions`，
并放一条**编译期自校验**（否则注入失效时 `vue-tsc` 不会报错，问题会拖到运行时）：

```ts
import type { ElementOptions, ElementType } from '@worm-vue3-print/core/designer'
type _TypeInjected = 'myElement' extends ElementType ? true : never
type _OptionInjected = 'myText' extends keyof ElementOptions ? true : never
const _injected: _TypeInjected & _OptionInjected = true
void _injected

declare module '@worm-vue3-print/core/designer' {
  interface PluginElementTypeMap { myElement: true }
  interface ElementOptions { myText?: string }
}
```

### 第 3 步：设计器入口（`import` 即注册）

在 `index.ts` 里把 Vue 组件挂到描述符的 `designer` 字段后注册一次。
canvas 的 `coreExtensions()` 会自动把它映射成素材卡 / 画布组件 / 属性 tab，
**不需要**再调旧 `registerElementExtension`（旧 API 仅作兼容别名保留）。

### 第 4 步：Node 入口（部署白名单）

`node.ts` 只 import `plugin.ts` 并注册，**绝不 import 设计器入口**（会把 Vue 拖进服务端）。
服务端 / Electron 宿主显式 `import '@acme/my-element/node'` 是安全边界：
模板字符串永远无法触发 `import()`，注册态即部署白名单。

### 第 5 步：宿主装配

```ts
// 设计器 / 浏览器：一行副作用 import 即可，渲染器按注册表自动收集
import '@acme/my-element'

// 服务端 / Electron 主进程
import '@acme/my-element/node'
import { collectExecutorBundles, createDomHostRuntime } from '@worm-vue3-print/core'
createDomHostRuntime(factory, loadExecutorBundle(), undefined, collectExecutorBundles())
```

## 3. 描述符契约签名表

| 字段 | 类型 / 签名 | 说明 |
| --- | --- | --- |
| `kind.id` | `string` | 插件唯一 id，写进 `plugins` 清单，也是 `configurePlugin(id, config)` 的键 |
| `kind.version` | `string` | strict 校验与执行器 bundle 按版本幂等去重 |
| `kind.type` | `string` | 元素 `type`，进入动态 kinds / draft enum / 注册表 typeIndex |
| `kind.icon` / `label` | `string?` / `string` | 素材卡与图层图标、标题 |
| `kind.fixedHeight` / `blocked` | `boolean?` | 分页口径（禁 autoHeight）/ 禁止 AI 生成 |
| `kind.requiredOptionKeys` | `readonly string[]?` | `print_element_kinds` 暴露给 AI 的必填属性 |
| `kind.defaultOptions` | `(partial?: Partial<ElementOptions>) => Partial<ElementOptions>` | 元素出厂默认，core 工厂与 canvas 素材卡共用 |
| `kind.optionMeta` | `Record<string, PluginOptionMeta>` | 专属属性元数据；并入了校验 knownKeys，避免旧模板冒 warning |
| `kind.notes` | `string?` | AI 提示词说明 |
| `legacyAliases` | `Record<旧名, 通用名>` | 兼容别名桥；主体只做通用查表转发，不含具体元素名 |
| `binding.bind` | `(options, data) => Record<string, unknown>` | 返回**运行时补丁**，不修改模板 JSON |
| `render.html` | `(spec: ElementRenderSpec) => string` | 无 `renderers` 时的兜底内联 SVG/HTML |
| `render.createRenderer` | `() => { render(spec): string }` | 进程内 SSR，三端首选路径 |
| `render.executorBundle` | `() => { name; version; code }` | 页面 IIFE；仅「只有页面执行器」的插件需要 |
| `designer.canvasComponent` | `unknown`（Vue 组件） | 设计器画布组件，props 与内置元素一致 |
| `designer.materialCard` | `unknown` | `{ label?, icon?, group? }`，素材卡与图层图标 |
| `designer.propertyTab` | `ElementPluginPropertyTab` | `{ id, label, component, hasProperties? }` |

`PluginOptionMeta.kind` 取值：`'mm' | 'pt' | 'count' | 'color' | 'bool' | 'text' | 'enum' | 'object'`；
`enum` 型另填 `enum?: readonly string[]`。

## 4. 属性台「自定义属性」tab

- 所有扩展元素**共用一个** tab，DOM 排在第一位；选中带专属属性的扩展元素时默认激活。
- 是否显示由实例级 `hasProperties(element)` 决定；省略时视为「有属性组件即显示」。
- 旧 `propertyComponent` 自动取得显示资格 —— 这是已装包宿主零改动的关键。
- 判据抛错时按「无属性」处理，绝不打断设计器。
- `searchKeywords` 让专属属性参与属性台搜索；缺省使用 tab 标题、扩展名与元素类型。

## 5. 校验的两种模式

| 模板顶层 | 模式 | 行为 |
| --- | --- | --- |
| 无 `plugins` 键 | legacy 宽松 | 未知 type / option 键只 warning（近拼写仍 error）；插件 `optionMeta` 声明的键不计 warning |
| 有 `plugins` 清单 | strict 严格 | 按注册态校验；缺插件 `MISSING_PLUGIN`，版本不符 `PLUGIN_VERSION_MISMATCH` |

历史模板**不要**补写 `plugins` 清单；新项目若希望「部署缺插件立刻报错」再声明。

## 6. 常见坑（都来自本仓库实践）

1. **改了 core 源码必须重建 dist**：canvas / echarts / MCP 通过 workspace import 读的是 core 的 `dist`，不重建会看到旧 API。
2. **注册表挂在 `globalThis` 固定 Symbol**：不要自己再建一份 `Map`，否则 monorepo / 双打包实例会「注册在这份、查表在那份」。
3. **`node.ts` 不能碰 Vue SFC**：服务端入口必须走纯 TS 链路，设计器组件只在主入口补充注册。
4. **页面执行器型插件要登记 `legacyAliases`**：执行器若只提供旧方法名，主体调 `renderAssets` 会经别名桥反查回落。
5. **进程内 SSR 与页面执行器是两条路径**：有 `createRenderer` 时不会注入 bundle、不会调用页面 `renderAssets`；
   写 fake driver 基线时别把「注入次数 / `renderCharts` 次数」按旧语义断言。
6. **ECharts SSR 的 zrender class 名是进程级递增计数器**：多渲染一次 `zr0-cls-0` 就变 `zr2-cls-6`。
   HTML 逐字基线必须保持原始用例顺序；新增对照用例放在后面并归一化 class 名。
7. **声明合并要放编译期自校验**：否则 `declare module` 写错时 TS 不报错，运行时才暴露。
8. **卸载要对称**：core 描述符与 canvas 响应式注册项要一起注销，否则素材卡残留。
9. **配置是惰性的**：`configurePlugin` 可在注册前调用、按键合并，不需要「注销 → 改配置 → 重注册」。
10. **架构守卫会拦裸渲染库**：出图端不能直接 `import 'echarts'` 等底层库，必须通过插件包与 core 执行器协议。
