# 渲染管线

本页说明模板 JSON 如何变成可打印的页面，以及浏览器预览与服务端 PDF 两条链路的用法。
三端为什么能保持一致、一致性如何保障，见 [三端渲染一致性方案](./三端渲染一致性方案.md)。

## 一、管线总览

无论浏览器预览、服务端 PDF 还是桌面客户端，核心流程在 `@worm-vue3-print/core` 中只有一份实现：

```
模板 JSON + printData
   │ 1. 数据绑定（bindData / injectSystemVariables）
   │    {field.path}、表达式、系统变量、表格明细行展开
   ▼
带数据的模板
   │ 2. 第一遍：生成测量 HTML，载入真实浏览器文档
   │    等待字体/图片就绪（waitReady）→ 读取元素实测高度（mm）
   ▼
测量结果 RawMeasurement
   │ 3. 分页计算（paginate）：页眉页脚、表格跨页重复表头、小计/汇总、
   │    连续纸内容高度探针（composeContinuousHeight）
   ▼
分页布局 PageLayout[] + 最终纸张尺寸 PaperMm
   │ 4. 第二遍：生成最终多页 HTML（@page 纸型/边距、矢量水印瓦片、
   │    条码/二维码 SVG、页码按分页结果回填）
   ▼
最终 HTML
   │ 5. 各端 driver 落地：
   │    浏览器：iframe 展示 / window.print()
   │    服务端：Playwright page.pdf() / page.screenshot()
   │    客户端：Electron printToPDF + 系统命令静默出纸
```

要点：

- 所有定位尺寸以**毫米**为基准，core 统一完成 px↔mm、mm↔英寸、mm↔μm 换算；
- 码制（条形码/二维码）渲染算法在 core 内统一，浏览器端以 jsbarcode/qrcode 库绑定生成 SVG；
- 出图参数（纸张、边距、背景色、缩放）由 core 的 PDF 目标规格推导，driver 只负责透传；
- 生成内容仅含 HTML/CSS/SVG（图片可为 URL 或 base64），不依赖宿主业务脚本。

## 二、浏览器端：免服务渲染

### 方式 A：直接使用 `PrintHtmlPreview` 组件（推荐）

```vue
<PrintHtmlPreview
  :template-json="templateJson"
  :print-data="printData"
  :base-url="baseUrl"
  @rendered="(pageCount) => ..."
  @error="(message) => ..."
/>
```

通过 ref 调用 `print()` 唤起浏览器原生打印（可在对话框中另存 PDF）、`rerender()` 强制重渲染。
组件内部完成两遍渲染并把最终 HTML 写入 iframe，props 变化自动重渲染（带渲染序列号防竞态）。

### 方式 B：直接调用 core/browser API

```ts
import { renderHtmlPages, browserCodeRenderer } from '@worm-vue3-print/core/browser'
import type { PrintTemplateData } from '@worm-vue3-print/core'

const result = await renderHtmlPages(
  templateJson as PrintTemplateData,
  printData,            // 对象或对象数组
  baseUrl,              // 相对图片基址，可省略
  browserCodeRenderer,  // 码制渲染器；不传由 runtime 自建（传入则沿用覆盖语义）
  { paperHeightMm: 120 }, // 可选：连续纸显式纸高覆盖（逃生门）
)

result.html        // 最终多页 HTML 字符串
result.pageCount   // 总页数
result.pageLayouts // 分页布局（调试/高级用途）
result.paperMm     // 最终纸张尺寸（mm，已含方向；连续纸为探针推导高度）
result.continuous  // 是否连续纸
```

该结果既可写入 iframe / 新窗口自行打印，也可直接交给静默打印 SDK 的
`client.printHtml(result, ...)`（见《静默打印》）。

### 浏览器 runtime

`createBrowserPrintRuntime()`（`@worm-vue3-print/core/browser`）= 共享 DOM 宿主 runtime
+ 隐藏 iframe driver，进程内直调 core DOM 执行器，不提供 PDF/截图出图能力。

## 三、服务端：render 微服务生成 PDF / PNG

`services/print-render` 是基于 Playwright（Headless Chromium）的私有微服务，
通过 workspace 软链依赖 core，与浏览器预览共用同一管线，仅 driver 不同。

### HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 健康检查，返回浏览器池状态（活跃数/并发上限/队列长度），无需鉴权 |
| POST | `/render/pdf` | 返回 `application/pdf` |
| POST | `/render/screenshot` | 返回 `image/png`（不分页单图，设计器叠层对比用） |

**请求头**：`X-Render-Key` 与环境变量 `RENDER_API_KEY` 一致（默认 `dev-render-key`）。

**请求体**（core 的 `RenderRequest`）：

```ts
interface RenderRequest {
  templateJson: object            // 必含 paperSize、orientation、margins
  printData?: Record<string, any>
  baseUrl?: string                // /docfiles/... 等相对图片的拼接基址
  paperOverride?: { width?: number; height?: number } // 宿主纸张覆盖（mm）
  paperHeightMm?: number          // 连续纸显式纸高（mm）逃生门
}
```

限制：请求体 10MB；单请求 30s 超时。错误响应统一为 `{ code, message }`，
code 包括 `UNAUTHORIZED`、`INVALID_REQUEST`、`RENDER_TIMEOUT`、`RENDER_FAILED` / `SCREENSHOT_FAILED`。

### 调用示例（浏览器经同源代理）

生产环境应由宿主后端反向代理，避免密钥进前端；demo 用 Vite 代理演示（`/render-api` → `http://localhost:3001`，代理层注入 key）：

```ts
const res = await fetch('/render-api/render/pdf', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ templateJson, printData, baseUrl }),
})
if (!res.ok) {
  const { message } = await res.json()
  throw new Error(message)
}
const pdfBlob = await res.blob()
```

服务部署（Docker、`PORT`/`RENDER_API_KEY`/`PLAYWRIGHT_CHROME_PATH` 环境变量、中文字体）见
`services/print-render/README.md`。

## 四、纸张与连续纸

- 内置纸型通过 `getPaperDimensions(template)` 解析；`CUSTOM` 使用 `customWidth/customHeight`；
- `CONTINUOUS`（热敏/标签）：设计画布固定高，纸宽取 `customWidth`（默认 80mm），
  实际出纸高度由管线在真实浏览器中探针测得内容高度 + 连续纸底边距推导（`composeContinuousHeight`，
  含最小高度），覆盖动态表格、合计签名等场景；
- 真机走纸公差不满足时，可用 `paperHeightMm`（服务端）或协议 `paperSize.height`（μm，客户端）显式覆盖。
