# 使用指南

本页介绍 worm-vue3-print 的核心概念、三种输出方式的选型，以及各专题文档的导航。

## 一、核心概念

### 1. 模板（TemplateData）

模板是一份纯 JSON，描述纸张与版面上的全部元素，由设计器产出、由宿主持久化，不含任何业务元信息（模板名称、业务类型由宿主自行管理）。主要字段：

| 字段 | 说明 |
|---|---|
| `paperSize` | 纸型：内置纸型（如 `A4`）、`CUSTOM`（自定义，配合 `customWidth/customHeight`）、`CONTINUOUS`（连续纸，配合 `customWidth`，默认 80mm） |
| `orientation` | `portrait` / `landscape` |
| `margins` | 页边距，单位 mm：`{ top, right, bottom, left }` |
| `header` / `footer` | 页眉/页脚区域（高度 mm + 元素数组），数据表格跨页时页眉重复 |
| `firstPageOverlay` | 首页叠加层 |
| `elements` | 内容区主体元素数组 |
| `unit` | 元素坐标单位；新模板固定 `'mm'`，旧数据无此字段时按 pt 自动迁移 |
| `pageBackground` | 页面背景色，默认白色 |
| `watermark` | 水印配置（密度、文字、透明度等，按显式矢量瓦片渲染） |
| `customWidth/customHeight` | 自定义/连续纸尺寸，单位 mm |

元素类型（`type`）：`text`（文本）、`longText`（长文本）、`image`（图片）、`table`（数据表格）、
`hline`/`vline`（线条）、`rect`/`oval`（形状）、`barcode`（条形码）、`qrcode`（二维码）、
`html`（HTML 片段）、`pageNumber`（页码）。每个元素的外观与绑定写在 `options` 中，
所有定位尺寸均为毫米。

### 2. 数据绑定与表达式

元素文本中用 `{字段路径}` 引用业务数据，如 `{supplier.name}`、`{goods.spec}`；
花括号内支持表达式（运算、函数调用），如 `{formatMoney(amount)}`、`{qty * price}`。
另有系统变量 `{printDate}`、`{printTime}`、`{pageIndex}`、`{totalPages}`。
详见 [表达式引擎](./表达式引擎.md)。

### 3. 业务字段（PrintBusinessField）

字段定义由宿主查询后以扁平数组 `PrintBusinessField[]` 传入设计器：

- `fieldKey` 是打印数据中的完整路径（如 `goods.spec`）；
- 字段树/表达式编辑器按首段自动分组：无点且作为其它字段前缀的记录为分组容器（如 `supplier`、`goods`）；
- `fieldType: 'list'` 的容器（如 `goods`）作为表格「列表数据源」选项。

### 4. 同构渲染管线

「同构」指浏览器预览、服务端 PDF、桌面客户端出纸共用 `@worm-vue3-print/core` 中唯一一套
渲染逻辑（数据绑定 → HTML 生成 → 测量 → 分页 → 码制渲染 → 纸张/PDF 规格推导），
各端只保留宿主 I/O 适配（iframe / Playwright / Electron 三个 driver）。
管线细节见 [渲染管线](./渲染管线.md)，一致性机制见 [三端渲染一致性方案](./三端渲染一致性方案.md)。

### 5. 单位

- 模板与渲染 API：毫米（mm）；
- 静默打印 WebSocket 协议的 `PrintOptions`：微米（μm），1mm = 1000μm；
- Electron `printToPDF` 参数内部由 core 从 mm 换算为英寸，调用方无需关心。

## 二、三种输出方式如何选型

| | 浏览器预览 / 原生打印 | 服务端 PDF | 桌面客户端静默打印 |
|---|---|---|---|
| 形态 | `PrintHtmlPreview` 组件，iframe 内渲染 | render 微服务（Playwright）HTTP 接口 | Electron 客户端 + 浏览器 SDK，WebSocket |
| 是否弹打印框 | 弹浏览器原生打印框（可手动另存 PDF） | 不弹，直接返回 PDF/PNG 二进制 | 不弹，直接出纸 |
| 适用场景 | 工位自检、临时打印、零部署 | 后端批量出单、归档、对外分发 PDF | 高并发工位、热敏/针式、连续纸、无人值守 |
| 依赖 | 仅 core + canvas | 需部署 render 微服务（Docker） | 工位机安装客户端；页面安装 SDK |
| 字体/内核 | 用户当前浏览器 | 服务端 Chromium（容器内字体需与模板一致） | 客户端内嵌 Chromium（工位机需装模板字体） |

选型建议：

- 只是让用户在页面上看效果、偶尔打印 → 浏览器预览即可；
- 业务系统需要生成 PDF 文件（下载、推送、归档）→ render 微服务；
- 仓储/物流等工位场景要求点一下直接出纸、打连续纸标签 → 桌面客户端 + SDK（推荐 `printHtml` 链路）。

三条链路的渲染结果在布局逻辑上同源；像素级一致还要求字体与 Chromium 内核同源，详见一致性方案文档。
